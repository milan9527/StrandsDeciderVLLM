# 1–128 并发：公网 GPU API 容量测试

[English](CONCURRENCY_128.md) | 简体中文

**2026-10-13**，放开原来的 8 请求准入和每秒 20 次速率限制，对真实服务依次测试 **1、2、4、8、16、32、64、128** 并发。

**12,800/12,800 次正式请求成功**，没有 HTTP 错误、限流拒绝或推理超时。所有响应的候选选择与原版一致；按原有 0.02 阈值，数值对齐通过 **12,799/12,800** 次。另有 **944 次预热请求** 全部成功，未计入性能统计。

后续 [8192 / 16384 / 32768 批次 token 测试](BATCH_TOKENS.zh-CN.md) 使用重新采集的基线，本文数据单独保留。

## 高并发复测

64 和 128 并发各再执行 1,280 次：

| 并发 | 成功 / 请求数 | 次/秒 | 平均 ms | P50 ms | P95 ms | P99 ms | 调用失败 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 64 | 1280/1280 | 29.65 | 2120.4 | 2142.8 | 2179.0 | 2838.1 | 0 |
| 128 | 1280/1280 | 29.65 | 4109.3 | 4297.5 | 5018.0 | 7469.6 | 0 |

扫描中观测到的最高吞吐为 **8 并发下 33.84 次/秒**。128 并发复测的 P95 为 **5.02 秒**。在当前配置下，接收更多并发请求主要增加等待时间，没有带来同比例的 GPU 吞吐增长。

GPU 按 **8192 token 的批次预算**调度请求。本轮每次输入 304–445 token，128 个已接收请求需要分多个批次处理；报告中的端到端延迟包含排队时间。

## 数值对齐异常

首轮 128 并发有一条 `underpaid/approve` 请求（index 27）超出数值阈值。两者都选择 `approved`，置信度从 0.5917 变为 0.6119，绝对差 **0.0202**，超过 **0.02**；候选概率最大差为 0.0151。延长复测没有数值失败。

原始记录保留这项数值对齐失败，没有放宽阈值，也没有用后续成功覆盖它。本轮没有单独定位该偏差的原因；如果业务使用置信度阈值，需要与候选 ID 是否一致分开验证。

## 配置与方法

| 项目 | 实际值 |
|---|---|
| 地址 | https://d1e9udi8st2p3g.cloudfront.net |
| 硬件 | 按需 EC2 `g6.xlarge`、NVIDIA L4、4 vCPU；容器内存上限 14 GiB |
| 模型 / 运行时 | 相同的 Decider v19 镜像；vLLM `0.31.0`；权重未变 |
| HTTP 准入 / 未完成问题数 | 256 / 256 |
| vLLM `max_num_seqs` | 128 |
| 速率拒绝阈值 | 每分钟 120,000 次，即每秒 2,000 次；突发容量 512 |
| 上下文 / 批次 token 预算 | 每问题 4096 / 每批次 8192 |
| GPU 显存比例 | 0.7 |
| 推理超时 / 客户端超时 | 25 秒 / 40 秒 |
| 缓存 / 执行 | Prefix caching、chunked prefill、CUDA Graphs 关闭 |

速率值是拒绝阈值，不表示这块 GPU 每秒能完成 2,000 次推理。本轮测试范围内没有触发准入或速率拒绝。

输入来自四个支付场景，每场景五步，每个请求含一个 choice 问题。客户端位于 GPU 主机之外，复用 HTTPS 连接，保持固定数量的 worker；每个 worker 收到响应后再发下一次请求，不自动重试。每档先单独预热 `max(20, 2 × 并发数)` 次。

吞吐量按全部正式请求的整体耗时计算；延迟分位数取成功响应的 nearest-rank。保留客户端和服务端耗时、HTTP 状态、唯一请求 ID、原始答案及逐响应对比。与原版的最大概率差、置信度差分别为 **0.0151**、**0.0202**。

这是针对本轮输入的短时容量测量，不能据此确定长上下文、多问题请求、长期可用性或业务准确率。[此前 1–32 并发复测](CONCURRENCY_RETEST.zh-CN.md) 的记录单独保留。

## 测试后的服务状态

已持久保留放开后的配置：HTTP / 问题准入 256、引擎上限 128，以及提高后的速率阈值。原来的 8 请求限制已解除。自动数值检查曾触发回退，随后重新启用并持久保留同样的配置，公网鉴权推理复核通过。

鉴权、请求体 / 上下文限制及推理超时继续启用。测试期间设置了自动恢复定时器，成功完成后已停止。
